It is shown to every signed-in account rather than to operators only, because the person it costs most is whoever is waiting on a release. Who the reviewers are, and how many, is deliberately not said either way. It says "any release that reaches human review" and not "nothing can be approved", because the second is false: release.Publisher.decide publishes a trusted owner's clean version bump of an already-listed plugin with no human involved, and that path never consults the reviewer set. */}} {{if .NoReviewers}}

This registry has no reviewers configured, so any release that reaches human review will wait indefinitely.

That is most of them: a plugin’s first release always goes to a person, and so does anything a quarantine rule flagged or anything from a publisher this registry has not marked trusted. Those releases are still recorded and their artifacts still downloaded and hashed — they simply queue, with nobody able to decide them. What still reaches the index on its own is a trusted owner’s clean version bump of an already-listed plugin, and marking somebody trusted is itself a reviewer-only action.

Moderation comes from control of the deployment and from nothing else, so the fix is to set REGSERVE_REVIEWERS to a comma-separated list of GitHub handles and restart the service. There is deliberately no way to grant it from inside here.

{{end}}

Claim a plugin id

An id is first come, permanent, and never recycled. It names your plugin in every installed copy on every user's machine, so it is never released or reassigned — not even after a delisting, and not by us. Claim the id your plugin's manifest declares, and check the spelling before you submit.

Claiming registers the id to your account and makes you its owner. It does not list anything. Your plugin appears in the index once a release of it has been approved, and the first release of a new id always goes to human review — whatever your trust level. The whole path is on the publishing walkthrough.
